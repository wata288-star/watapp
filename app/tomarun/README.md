# TOMARUN モバイルUI プロトタイプ

開発者向け資料（FLYHEIT 2026.07）の内容をもとに、エンドユーザー（現場作業者）向け
モバイル画面を実装したもの。`/tomarun` 以下で動く。既存の watapp とは独立していて、
スタイルは `tomarun.css` に閉じている（`.tm` スコープ）。

## 資料からそのまま反映した点

- **ホームは2ボタンのみ。** 確定デザインどおり、上部にメーカー名と通知ベル、中央に
  トラブルシューティングと動画マニュアルのカードを2枚だけ。第3のボタンは足していない。
  中断中の診断はカード内のバッジで示し、導線を増やさずに再開できるようにした。
- **タブは4つ**（ホーム・記録・資料集・メニュー）。
- **動画への導線は2ルート。** ルートAは推奨処置の結果画面から該当動画へ直結、
  ルートBはホーム → 動画マニュアル → 機種 → 部位。
- **記録は5ステップをやめて1画面に集約。** 発生日時・担当者は自動、アワーメーターは
  推定値を出して確定タップのみ。原因分類と定型文はチップ、写真は最初に置いた。
  文字入力は任意で、音声はあくまで補助として二次ボタンに下げている。
- **入口A（実質1タップ）。** 結果画面で「解決した」を押すと、ツリーで通った確認項目が
  チェックリストとして入り、その下に「上記を確認した上で◯◯」の処置文が続く下書きが
  できあがる。所要時間は開始→解決を自動計測。
- **取説は項目単位。** 警告・注意は原文のまま専用ブロックで表示し、図はタップで拡大・
  ダウンロード不可。エラーコード検索から項目へ直結、お気に入りは項目単位、
  お気に入りした項目だけをオフライン保存する。

## 現場向けに固定した約束事

`tomarun.css` の先頭にトークンとしてまとめてある。

- タップ領域は最小 56px（`--tm-tap`）。選択肢ボタンは 76px。
- 本文は 15px 以上、入力欄は 16px（iOS の自動ズーム防止）。
- 文字入力は常に任意。音声入力は二次ボタンに置く。
- 警告・注意・禁止は専用ブロックで、要約せず原文のまま。
- オフラインで読める／保存済みの状態は、画面上で必ずバッジとして見せる。

## ホワイトレーベル

ロゴ（`components/BrandHero.tsx`）とテナント名は差し替え前提。配色は `.tm` の
CSS カスタムプロパティを上書きするだけでメーカーごとのブランドに変えられる。

## データ

`lib/data.ts` はすべてモック。実装時はテナント単位に分離した API から取得する。
