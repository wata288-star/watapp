# TOMARUN コマンドセンター 取扱説明書

TOMARUN の事業展開（営業・展示会・マーケ・資金調達・プロダクト）を
1つの画面で管理するためのツールです。

アクセス先： **`/pm`**（例：`http://localhost:3000/pm`）

既存のチャットアプリ（`/`）とは完全に分かれているので、
どちらを触ってももう一方には影響しません。

---

## 1. 何ができるのか（13モジュール）

| メニュー | できること |
| --- | --- |
| **ダッシュボード** | 今日やるべきこと、パイプライン、期限超過タスク、リスク、注目ニュースを1画面に集約 |
| **ガントチャート** | 部門横断のスケジュール。日/週/月で切り替え、マイルストーンと本日ラインを表示 |
| **タスクボード** | カンバン形式。カードをドラッグしてステータス変更 |
| **OKR / KPI** | 四半期の目標と成果指標。数字はその場で書き換え可能 |
| **商談パイプライン** | 顧客管理（CRM）。カンバン／一覧表、加重売上の自動計算、CSV出力 |
| **トークスクリプト** | シーン別の営業台本、想定問答12件、競合バトルカード4枚 |
| **営業資料ライブラリ** | 資料の台帳。商談ステージ別に「いつ何を出すか」を整理 |
| **ROIシミュレーター** | 顧客の数字を入れてその場で投資対効果を試算。提案書用テキストを出力 |
| **展示会マネジメント** | 出展計画、準備チェックリスト、獲得リード管理、リード単価の自動計算 |
| **マーケ施策・記事** | チャネル別の施策とKPI、コンテンツカレンダー |
| **業界ニュース** | 毎日 8:00 / 18:00 に自動収集。関連度スコア付き |
| **資金調達** | 投資家パイプライン、必要書類チェックリスト、ラウンド進捗 |
| **ナレッジ / リスク** | 意思決定ログ、商談の学び、議事録、リスク管理表 |

初期データには、アップロードいただいた 4 つの資料
（パンフレット改善提案書／新価格体系・プラン提案書 v5／ROI提案書／OEM収益化戦略デック）と
ROI シミュレーター Excel の内容が入力済みです。すべて画面上で編集できます。

## 2. まず触ってみる順番（おすすめ）

1. **ダッシュボード** を開く → 全体像をつかむ
2. **商談パイプライン** でカードをドラッグしてみる → 加重パイプラインの数字が変わる
3. **ROIシミュレーター** で数字をいじってみる → 回収期間がリアルタイムで変わる
4. **業界ニュース** で「今すぐ取得」を押す → 実際のニュースが集まってくる

---

## 3. 業界ニュースの自動収集について

### いつ集まるのか
サーバーが動いている限り、**毎日 8:00 と 18:00（日本時間）** に自動で集めます。
サーバーが止まっていた場合は、次にニュース画面を開いたタイミングで
「前回の配信時刻を過ぎている」と判断して自動取得します。

### 何を集めているのか
初期状態では 8 つのソースを登録しています。

- 製造業DX / 予知保全・設備保全 / 技能継承・人手不足 / 産業機械メーカー動向
- 生成AI × 製造業 / スマートファクトリー / 補助金・支援制度 / ITmedia MONOist

### 関連度スコア
「ダウンタイム」「技能継承」「属人化」「アフターサービス」など、
TOMARUN の営業に効くキーワードを含む記事ほど高くなります（0〜100）。
**おすすめ順**で並べると、関連度の高い記事が上に来ます。

### キーワードを増やす
「収集ソース」ボタン → キーワードを入力して追加。
例：`射出成形機 保守` と入れると、そのキーワードのニュースが毎日集まります。

### 使い方のコツ
営業に使えそうな記事に **★（スター）** を付け、「メモ」に
「◯◯社への次回訪問で切り出しに使う」と書いておくと、商談前の準備が一瞬で終わります。

## 4. ROIシミュレーターの計算式

アップロードいただいた `tomarunroisimulator.xlsx` の構造を再現しつつ、
「なぜその金額になるのか」を商談中に説明できるよう、各項目を分解しています。

```
月次効果 = ① 人件費削減 + ② ダウンタイム回避 + ③ 部品受注の増加 + ④ OEM再販収益

① 人件費削減   = 月間件数 × (従来分 − 導入後分) ÷ 60 × 時間単価 × 効果発現率
② ダウンタイム回避 = 年間発生回数 × 1回あたり損失 ÷ 12
③ 部品受注の増加  = 年間受注件数 × 増加率 × 1件あたり粗利 ÷ 12
④ OEM再販収益   = 顧客社数 × 1社あたり月額   （プレミアムOEMプランのみ）

投資回収期間 = 累積収支（初月に初期費用をマイナス計上）がプラスに転じる月
```

**効果発現率** は「全件で効果が出るわけではない」ことを織り込む安全係数です（標準 60%）。
商談では、この係数を下げてもなお回収できることを見せると説得力が上がります。

初期値は Excel と同じ前提（月50件・120分→5分・時間単価5,000円・効果発現率60%）で、
スタンダードプランなら **年間効果 約575万円 / 回収3ヶ月 / 1年目ROI 161%** になります。

## 5. データの保存場所

すべて `data/pm-state.json`（サーバー上の JSON ファイル）に保存されます。

- 入力するとすぐ保存されます。「保存ボタンを押し忘れた」は起きません。
- 同じサーバーにアクセスする人は全員が同じデータを見ます。
- `data/` は Git 管理外です（`.gitignore` 済み）。
- **バックアップはこのファイルをコピーするだけ**です。
- 保存先を変えたい場合は環境変数 `PM_DATA_DIR` を設定してください。

### 初期データに戻す

```bash
curl -X DELETE http://localhost:3000/api/pm/state
```

⚠️ 入力した内容はすべて消えます。実行前に `data/pm-state.json` をコピーしておいてください。

## 6. 起動方法

```bash
npm install
npm run build
npm start          # http://localhost:3000/pm
```

開発中は `npm run dev` でも動きます（自動リロードあり）。

## 7. 技術的な構成（引き継ぎ用）

```
lib/pm/
  types.ts    ドメイン型とマスタ定義（プラン価格・商談ステージなど）
  seed.ts     初期データ（資料から抽出した内容）
  store.ts    JSON ファイル永続化（Node ランタイム専用）
  roi.ts      ROI 計算モデル（純粋関数・クライアント/サーバー共用）
  news.ts     RSS 取得・解析・スコアリング・配信スケジュール判定

app/api/pm/
  state/                  全体の読み込み / 初期化
  [collection]/           一覧取得・作成
  [collection]/[id]/      更新・削除
  newsfeed/               ニュース取得（スロット超過時は自動更新）
  newsfeed/refresh/       ニュース強制取得

app/pm/
  layout.tsx        PmProvider + サイドバーシェル
  _lib/store.tsx    クライアント状態管理（楽観的更新）
  _lib/format.ts    表示フォーマットと日付ユーティリティ
  _lib/derive.ts    商談の派生値計算
  _components/      Shell / Gantt / Kanban / 共通UI
  <各モジュール>/page.tsx
```

- 外部ライブラリの追加はゼロ（RSS 解析も自前実装）
- ニュースの定期実行は `server.js` の `startNewsScheduler()` が担当
- `.pm-root` 配下にスタイルをスコープしているため既存アプリと干渉しません

## 8. 今後の拡張候補

現時点で入っていないもののうち、効果が大きそうな順です。

1. **メール連携** — 商談の「次アクション」期日が来たらメール通知
2. **ログイン・権限管理** — 現在は誰でも全データを閲覧・編集できます。社外の人に見せる前に必須
3. **請求・入金管理** — 受注後の請求書発行と入金消込
4. **顧客オンボーディング進捗** — 資料受領 → AI分析 → リリースの4ステップを顧客ごとに追跡
5. **提案書の自動生成** — 商談データと ROI 試算から提案書 PDF を組み立て
6. **競合の動きの自動監視** — ニュース収集にライバル社名を登録して動向を追う
